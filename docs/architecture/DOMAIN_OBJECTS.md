# عقود المجال للعالم والأندية

هذه مواصفات تصميم. ترشد الأسماء التالية توزيع الملكية والمسؤوليات عند التطبيق. تبدأ كل ميزة بواجهة صغيرة تستخدمها التطبيقات الأخرى، مع ملف منفصل لكل مسؤولية بحجم قابل للمراجعة.

| نوع المجال | ما يملكه | كيف يركّب |
|---|---|---|
| JurisdictionProfile | معرف بلد ونسخة ومجموعة سياسات وتواريخ سريان | قراءة فقط خلال تقييم صفقة؛ يركّب التجارة والعملة والتمويل من بيانات مستقلة |
| TradePolicy | قرار أهلية + رمز السبب والمصدر والفترة | يقيّم المنشأ والوجهة وتصنيف السلعة والأطراف. تقدير التكلفة يأتي من سياسة منفصلة بعد القبول |
| SupplyNetwork | وصلة وممر ونافذة سعة، وحجوزات وترتيب أولوية | يسند الحجز إلى وصلة فعلية. يمكن لكل قطاع اختيار استراتيجية مقارنة المسارات |
| CounterpartyRelationship | ثقة وائتمان والتزامات بين طرفين وسجل تغير | يحدّثه حدث مؤرخ، وتستهلكه سياسة الائتمان أو التفاوض مع بقائه منفصلًا عن الأهلية |
| AcquisitionCase | مراحل العرض والفحص والموافقات والإغلاق | سياسات حقوق التصويت وتركيز السوق والمالية والتوريد، بحسب الكيان والولاية |
| ExposureAssessment | مدخلات الضغط والنتيجة والمساهمة والتغطية | قواعد تطبيع مرقّمة، ثم سياسة ثبات الدرجة ودورية المراجعة من جلسة الفردي |
| ClubGovernance | أدوار ونطاق وسقوف ومراجعة معتمدة | مصفوفة أدوار وصلاحيات، مع سياسة تصعيد إلى مجلس أو إدارة عند تجاوز الحد |
| ScoutingAssignment | مهمة الكشاف وتغطيتها وتقريرها وثقتها وتاريخها | نماذج تقييم مختلفة حسب المركز والدوري، تستدعيها مديرية الرياضة وفق ميزانية |
| TransferCase | عروض وحجوزات وشروط وموافقات وتسجيل | يستعمل تفويض النادي والمالية، وRegistrationPolicy التي يملكها مُعرّف المنافسة والاتحاد |
| CompetitionSeason | الموسم والمراحل والأهلية والتقويم والنتائج والترتيب | SchedulePolicy لكل مسابقة، ومحرك نتيجة صغير يعمل على الحالة الرياضية وليس كائنًا ضخمًا |

## تدفق الأمر والحالة

- تحمل الأوامر معرف الأمر والفاعل والكيان والمراجعة المتوقعة ووقت المحاكاة ومدخلات تحقق السياق. يقيم الخادم تفويض الفاعل عند اللعب المتصل، ويقيم المضيف المحلي القواعد نفسها في الفردي.
- تعطي المعاينة نتيجة قابلة للقراءة، من دون حجز أو أثر مالي. عند التثبيت تُعاد أهلية الصفقة تحت القاعدة النافذة والمراجعة الحالية. تغيير نافذة أو سعة أو تفويض ينتج رفضًا مفهومًا. تعيد المحاولة بمعرّف وبيانات مطابقين الإقرار السابق.
- يستعمل قرار مركّب سياسة كل مالك من خلال عقد عام. مثلًا حصول الصفقة على التمويل لا يغير ملكية الهدف؛ إغلاقها هو الذي يثبت تغيير الملكية والقيود في عملية واحدة. لا يحجز النادي مبلغًا أو أهلية بمجرد الضغط على معاينة العرض.
- يتخذ المنافس قرارًا قابلاً لإعادة التشغيل وفق تسلسل ثابت: توليد بدائل من إمكاناته، تصفية غير المؤهل، ترجيح العائد والمخاطر، اختيار حسب سياسة وإطار ميزانية، ثم إصدار أمر عادي. عند التعادل يُستخدم ترتيب ثابت أو بذرة الجلسة. تظهر النتيجة للواجهة دون منح جهة عرض سلطة كتابة.
- تستقبل الواجهة إسقاطات ثابتة لأسباب التعرفة والصعوبة والرفض والقرارات المعلقة. تتحول مفاتيح الأسباب إلى رسائل مترجمة. تحفظ الأحداث معرف السبب والتاريخ والنسخة، ويمكن مقارنة نتائج الحفظ المُعاد بالدفعة الأولى.

## الحدود القابلة للمراجعة

توضع القيم البسيطة والحسابات المستقلة في دوال قابلة للاختبار، وتستخدم الكائنات لحماية انتقالات الحالة والموارد والملكية. الأدوار تركيب بين صلاحية وميزانية وسياسة تعيين، وملف البلد بيانات وسياسات، دون صنف فرعي لكل دولة أو دور أو نادٍ. لا يقرأ مجال القواعد وقت النظام أو حالة الواجهة أو أسعارًا فعلية من الشبكة أثناء العملية. تقسّم وحدات العالم والأندية إلى ملفات متماسكة وتظل تحت [الحد الموثق](../engineering/STANDARDS.md#تنظيم-الميزات-وحجم-ملفات-الكود).
