# ADR-0012 — TypeScript للمحاكاة وRust/WebAssembly وفق القياس

**الحالة** معتمد بتوجيه صاحب المشروع. اختيار أي جزء يُنفّذ بـRust قرار تابع لنتائج القياس.

## القرار

- TypeScript بوضع strict هو اللغة الأساسية للواجهة، وعقود المجال، والمحاكاة، والمالية، والسوق، وإدارة الأندية. تُغلّف واجهة الويب بـCapacitor للهواتف وفق [ADR-0001](ADR-0001.md).
- يبدأ التنفيذ بمحاكاة TypeScript مستقلة عن الواجهة. يشغّل المضيف المحلي تلك المحاكاة داخل Web Worker، ويشغّل الخادم نفس قواعد المجال في بيئة خاضعة له في الموسم المتصل.
- نرتّب الأحداث بوقت المحاكاة وأولوية ثابتة. عند تغير طريق أو سياسة أو موعد نعيد حساب الكيانات المتأثرة، وفق ترتيب إغلاق اليوم المعتمد. ترسل الواجهة أوامر ذات إصدارات وتستقبل تقدمًا ونماذج قراءة مضمّنة بالمراجعة.
- يُقيّم Rust المترجم إلى WebAssembly للعمليات الحسابية التي تفشل في ميزانية الأداء بعد تحسين الخوارزمية أو نقل البيانات. يبدأ التقييم بوحدة واحدة مثل تقييم مسارات الإمداد أو تخصيص الطلب أو دفعة مباريات. يفصل عقدها الإدخال والحساب والإخراج. إشراف المالية والإذن وتثبيت الحالة من مسؤولية المجال.
- يمرر التطبيق مجموعة بيانات أو عملية كاملة عبر العقد ويستلم نتائجها في دفعة. يحتفظ الحفظ بصيغة ثابتة ومعرّفات وإصدارات وقواعد تقريب وبذرة. تُطبق قاعدة 350 سطرًا على ملفات TypeScript وRust اليدوية.

## متى نحول وحدة إلى Rust

تقارن [خطة القياس](../engineering/PERFORMANCE.md) نسختي إنتاج بوحدة وبيانات وقواعد متطابقة، وتحسب أثر التحويل إلى البيانات ونقلها، وتهيئة WebAssembly، وإخراج النتيجة. يعتمد CTO الانتقال عندما يعالج عنق الزجاجة في الزمن الذي يلاحظه اللاعب على الأجهزة المستهدفة، ويحقق ميزانيات الذاكرة والاستجابة ويجتاز إعادة التشغيل. إذا حقق TypeScript الميزانيات أو بقيت كلفة التكامل أكبر من المكسب المقاس، يستمر تنفيذ TypeScript. عند النقل، تملك كل قاعدة مسار تنفيذ مرجعي واضحًا. أي تنفيذ بديل مطلوب للتوافق يخضع لاختبار تكافؤ ويُحدد دعم المنصات من أدلة القياس.
