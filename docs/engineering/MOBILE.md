# بناء لعبة الأعمال للهاتف وقياسها

يشغّل غلاف Capacitor رحلة «الطلب الكبير» بنفس بناء الإنتاج `apps/game/dist/` والعامل من بناء الويب. تبقى مشاريع `android/` و`ios/` محلية ويعيد أمر التجهيز إنتاجها باستخدام الإصدارات المثبتة في `package-lock.json`. تستخدم الرحلة IndexedDB وتطلب حفظ آخر حالة مؤكدة عند الانتقال إلى الخلفية وعند العودة. يستأنف العامل من آخر حفظ مكتمل بعد إعادة فتح التطبيق. يظل يوم المحاكاة ثابتًا أثناء غياب اللاعب.

## البناء

ابدأ بـ `npm ci` على Node.js 22 من جذر المستودع. جهّز JDK 21 وAndroid SDK Platform 35 وBuild Tools 34.0.0 لبناء Android. يحتاج بناء iOS إلى macOS وXcode 16 أو أحدث.

```sh
npm run prepare:mobile -- android
(cd android && ./gradlew assembleDebug)
```

ينتج البناء `android/app/build/outputs/apk/debug/app-debug.apk`. افتح المشروع عبر `npx cap open android` أو ثبّت الحزمة على جهاز متصل عبر `adb install -r android/app/build/outputs/apk/debug/app-debug.apk`.

```sh
npm run prepare:mobile -- ios
xcodebuild -project ios/App/App.xcodeproj -scheme App -sdk iphonesimulator \
  -configuration Debug CODE_SIGNING_ALLOWED=NO build
```

افتح المشروع عبر `npx cap open ios` واختر فريق التوقيع والجهاز لاختبار النسخة على iPhone. يستخدم المشروع Swift Package Manager. يختار أمر التجهيز قالب SPM عند الإنشاء مباشرة لتجاوز مشكلة معالجة خيار مدير الحزم في Capacitor 7.6.10.

## مصفوفة التحقق

العرض الأصلي المطلوب لبوابة B هو Android أولًا. يُستأنف تحقق iOS بعد اعتماد شريحة Android. [خارطة الإنتاج](../production/ROADMAP.md)

| البيئة | الإصدارات | التحقق المطلوب |
|---|---|---|
| Android متوسط | Google Pixel 6a بذاكرة 6 GiB وAndroid 15 ‏(API 35). سجّل إصدار Android System WebView المثبت عبر `adb shell dumpsys webviewupdate`. | تشغيل الحزمة وقياس الأداء والاستعادة والمناطق الآمنة على الجهاز بانتظار التحقق. |
| iOS | iPhone 13، يستهدف iOS 18 أو أحدث. سجّل إصدار النظام الفعلي وبيانات WKWebView في Safari Web Inspector. | بناء Xcode والتشغيل وقياس الأداء والاستعادة والمناطق الآمنة مؤجّلة. |
| معاينة التطوير | Chromium على Linux في عرض هاتف 390×844 بكسل | فحص واجهة الويب والحفظ وقياسات TypeScript الأولية. |

اختبر اتجاهي الشاشة بأوضاع العربية والإنجليزية، والتفاف المحتوى حول الحواف، والوصول إلى شريط التنقل. بعد ظهور مؤشر الحفظ، أرسل التطبيق إلى الخلفية ثم أعد فتحه. أوقف عملية التطبيق بعد الحفظ وأعد تشغيله مجددًا. قارن يوم المحاكاة والمراجعة والكمية المسلّمة والرصيد بآخر حفظ مكتمل في الحالتين. استخدم Chrome DevTools لمضيف Android وSafari Web Inspector لمضيف iOS لتسجيل القياسات.

## عينة الأداء وميزانياتها

استخدم سيناريو «الطلب الكبير» الافتراضي ببذرته وقواعده المثبتة. أسّس شركة واحدة، ووقّع عقدًا واحدًا، واطلب شحنة واحدة، ثم سلّم 50 وحدة و20 وحدة على دفعتين. تبدأ عينة الدفعة من حفظ اليوم 19 وتقدّم 12 يومًا إلى اليوم 31، مرورًا بإقفال اليوم 30. تحتوي العينة فاتورتين من التسليم، مع صفر أندية ومباريات. أعد استخدام حفظ اليوم 19 لدفعة الإقفال، وحفظ اليوم 31 لقياس الفتح.

| المقياس | الميزانية الأولية على الأجهزة المستهدفة |
|---|---:|
| الإقرار المرئي المحلي P95 | أقل من 100 مللي ثانية |
| فتح جلسة محفوظة P95 | أقل من 3 ثوانٍ |
| دفعة 30 يومًا افتراضيًا P95 | أقل من ثانية واحدة |
| ذروة ذاكرة JavaScript للمضيف والعامل مجتمعين | 64 MiB أو أقل |

تغطي عينة اليوم 19 إلى 31 التنفيذ المتاح لرحلة الشريحة. تتطلب ميزانية 30 يومًا عينة موسّعة بموجب خطة الأداء. اجمع ذاكرة JavaScript للمضيف والعامل أو سجّل الأجزاء التي لا تعرضها أداة المنصة.

ابدأ معاينة ويب إنتاجية بأمري `npm run build:game` و`npx vite preview apps/game`. فعّل القياس عبر `?performance=1` في المعاينة أو افتح مدخل الرحلة بالاستعلام نفسه من أدوات فحص WebView على نسخة تصحيح. استخدم `performance.getEntriesByType('measure')` لقراءة مدد القياس وبيانات اليوم والمراجعة المرفقة. يحدد القياس المرئي الإطار الثاني بعد تحديث الواجهة تقريبًا لوقت ظهور التغيير.

| القياس | البداية والنهاية |
|---|---|
| `empire.open` | بدء تنقّل الصفحة إلى عرض النموذج المستعاد |
| `empire.worker-ack` | بدء أمر اللعبة إلى استلام إقرار العامل |
| `empire.visible-ack` | بدء الأمر إلى فرصة ظهور الإقرار أو النتيجة السريعة |
| `empire.worker-result` | بدء الأمر إلى وصول نتيجة العامل القابلة للعرض |

كرّر الدفعة والفتح الدافئ والبارد 20 مرة لكل مقياس. ثبّت الحفظ والبناء وإعداد العرض، وسجّل الوسيط وP95 بأخذ الرتبة 19 من 20 بعد ترتيب الأرقام تصاعديًا. افصل ظروف الفتح البارد والدافئ وسجّل كيفية تفريغ الذاكرة المؤقتة. عند قياس الفتح من الأيقونة، قس من لحظة بدء التشغيل الأصلي إلى ظهور جلسة الحفظ وسجّل هذه المدة إلى جانب توقيت WebView. سجّل الجهاز والنظام وإصدار WebView ومعرّف الالتزام مع النتائج.
