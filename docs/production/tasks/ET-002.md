## نطاق التسليم

المسارات المقصودة هي packages/contracts/ وpackages/simulation/. تحدد بنية المستودع الفعلية المسار داخل تلك الحدود.

نفّذ غلاف الأمر والنتيجة ومعرّف الجلسة والمراجعة والوقت الافتراضي وترتيب إغلاق اليوم؛ ثبّت عقد التقدم والإيقاف عند تنبيه. اكتب المحاكاة بـTypeScript strict واعزلها خلف عقد يمكن للمضيف المحلي والخادم استخدامه.

## معايير القبول

- اختبار يساوي فيه تقدم 5 أيام خمس خطوات
- تساوي اللقطة مع إعادة نفس السجل والبذرة
- إعادة المعرّف نفسها بلا أثر إضافي والحمولة المختلفة conflict
- رفض الأمر المتقادم قبل التعديل.
- يعمل عقد المحاكاة في اختبار headless دون DOM أو Capacitor أو قراءة وقت النظام. تُعرّف رسائل المعرف والمراجعة والتقدم والنتيجة عند حد المضيف.

## حدود المهمة

اترك المصروفات والتكاليف لمجال Finance.

## دليل الإنجاز

تحقّق محليًا على Linux باستخدام Node.js 22.23.5 وTypeScript 5.9.3 وVitest 3.2.7.

| التحقق | النتيجة الفعلية |
|---|---|
| تقدم خمسة أيام مقابل خمس خطوات، وترتيب الإغلاق اليومي والشهري | تطابقت اللقطتان بما فيهما اليوم والمراجعة وحالة العشوائية. نُفّذت المراحل اليومية بالترتيب، ثم الإقفال الشهري بعد اليوم 30. ترتّب العمل داخل المرحلة حسب الوقت الافتراضي ثم التسلسل ثم المعرّف. |
| إعادة التشغيل والتكرار والتعارض | أعاد السجل المتسلسل والبذرة نفسها اللقطة وإقرارات الأوامر. أعاد تكرار المعرّف بالحمولة نفسها الإقرار الأصلي، ورُفض تغيير حمولته برمز `conflict`. |
| الأمر المتقادم وفشل قاعدة أثناء دفعة | رُفض الأمر المتقادم قبل استدعاء القواعد. لم تتغير اللقطة أو السجل عند فشل قاعدة في اليوم الثاني، ونجحت إعادة المحاولة بالمعرّف نفسه بعد زوال الفشل. |
| تنبيه القرار وحدود المضيف | توقفت دفعة اليوم 35 بعد إغلاق اليوم 30، بما فيه الإقفال الشهري. استؤنف التقدم بعد حل جميع تنبيهات اليوم. رُفضت الرسائل المشوهة وأوامر الجلسات الأخرى. |
| فحوص المستودع | اجتاز `npm run check:file-size` فحص 25 ملفًا يدويًا. نجح `npm run typecheck`، واجتاز `npm test` 17 اختبارًا منها 9 تخص ET-002. نجح `npm run build` للمدخلين ونجح `git diff --check`. |

شُغّلت المحاكاة عبر عقد المضيف في بيئة Node دون DOM أو Capacitor أو ساعة النظام. في محاولة أولية على Node.js 24 داخل بيئة العمل، وصلت مخرجات العمليات الفرعية فارغة في اختبارات أدوات ET-001. اجتازت الاختبارات كلها على Node.js 22 المعتمد. ربط Web Worker ضمن [ET-013](ET-013.md)، والتحقق على الأجهزة ضمن [ET-014](ET-014.md).

### قرارات التنفيذ

- تبدأ الجلسة باليوم المفتوح 1 والمراجعة 0. ترتفع المراجعة مرة لكل يوم مغلق ولكل تنبيه محلول، ويُسجّل تسلسل مستقل لكل أمر مقبول داخل الجلسة. بذلك تتطابق مراجعة العالم بين الدفعة والخطوات اليومية.
- يقبل عقد الإصدار الأول عدد أيام أو تاريخ إغلاق شامل، حتى 360 يومًا لكل أمر. يثبّت يوم التنبيه كاملًا قبل التوقف ويعيد نتيجة التقدم مع الإقرار. يمثّل أمر حل التنبيه إزالة قرار من قائمة الانتظار، وتضيف مهام المجال لاحقًا قواعد القرار وآثاره.
- تُستعاد الجلسة من البذرة وجدولة القواعد نفسها والأوامر الفريدة بترتيب ورودها. تُحفظ إقرارات الرفض الصحيحة ضمن الجلسة حتى تعيد المحاولة نتيجتها الأصلية. تبقى المهام التابعة مخططة إلى أن تجتاز تبعياتها الأخرى.
