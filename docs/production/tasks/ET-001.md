## نطاق التسليم

المسارات المقصودة هي package.json وملف قفل التبعيات و.github/workflows/ وtools/ وapps/game/ وملفات النموذج السابق التي تحتاج تنسيقًا أو فصلًا للالتزام بالمعايير. تحدد بنية المستودع الفعلية المسار داخل تلك الحدود.

ثبّت تثبيت الحزم وفحصها، سجّل وضع النموذج السابق، وأنشئ حد دخول واضحًا للعبة الجديدة وخريطة بناء للحزم. أضف فحص حجم الملفات ووثّق طريقة تشغيله محليًا. نسّق ملفات النموذج المضغوطة وقسّمها حسب المسؤولية إذا تخطت السقف بعد التنسيق، مع اختبار سلوكها.

## معايير القبول

- أثبت أن تثبيتًا جديدًا وبناءً واختبارات النموذج يعملون
- بيّن سبب أي فشل حالي قبل إيقاف النموذج
- أنشئ نقطة دخول للعبة الجديدة قابلة للتشغيل من README وحدًا يمنع تسرب اعتماد DOM إلى المجال.
- وفّر أمرًا محليًا مثل npm run check:file-size، وشغّله في CI لطلبات الدمج. يغطي الفحص كل ملفات الكود اليدوي في المستودع وفق معايير الهندسة، ويطبع المسار وعدد الأسطر ويعيد حالة فشل عند وجود مخالفة.
- أثبت بأمثلة قابلة للتكرار قبول 200 و350 سطرًا ورفض 351 سطرًا، مع عدّ الأسطر الفارغة والتعليقات والسطر الأخير غير المنتهي بمحرف سطر جديد. تحقق من تطبيق الاستثناءات الموثقة على البيانات ومخرجات التوليد مع بقاء الأكواد اليدوية مشمولة.
- وثّق داخل الكود غرض الوحدات الجديدة وعقودها المؤثرة، وسجّل نقطة الدخول ومسارات القواعد والاختبارات في بطاقة المهمة.
